# Lesson — t-p0-wire (venue round-trip wire-miss)

## 진단 (5-axis live audit)
production paper loop 이 **실제 demo 주문을 한 번도 안 보냄**.
- open `_production_pipeline.py` + close `_production_close.py` 둘 다 **simulate-only**.
- `--real-roundtrip` flag 가 폐기되어 venue adapter (`open_position`/`close_position`) 미호출.
- 결과: `data/polaris.sqlite` 17,259 fills 전부 **가짜** (simulate 산출물). PnL/learner 신호 오염.

## Fix
builder 가 TDD 로 real_roundtrip wire 복구 → 618 tests green.

## 핵심 교훈 — builder ≠ reviewer 의 실증
**618 green tests 가 실주문 안전 P0 5건을 못 잡았다.** green 통과한 그 코드에서
codex 외부 review 가 5건 포착:
1. db 혼재 (가짜+실주문 동일 db).
2. adapter 예외 시 allocator reservation 누수.
3. confirm/persist 실패 시 orphan 실포지션 (venue 엔 열렸는데 내부 미기록).
4. Capital `deal_id` restart 유실.
5. `pnl_r` 오산.
builder 재수정 → codex 재review **7/7 resolved, safe=yes** → 627 tests green.

테스트는 "내가 의도한 것" 만 검증한다 (confirmation bias). 실주문 안전처럼
설계자가 미처 상상 못 한 failure mode 는 **외부 reviewer 만** 잡는다.
green ≠ safe. [[ADR-009-harness-collaboration-protocol|ADR-009]] builder≠reviewer 원칙이 가설이 아니라 비용으로 증명됨.

## 영속 규칙
- 실주문/실자금 경로 touch → green 무관하게 codex 외부 review 의무.
- 가짜 fills db 와 실주문 db 는 물리 격리 ([[ADR-010-venue-roundtrip-activation|ADR-010]]: `polaris_live.sqlite`).
- orphan (venue open / 내부 미기록) → `risk_events` 강제 emit, 검증 시 0 확인.
