## Fills ledger (Day 6 §3)

DDL:
```sql
CREATE TABLE fills (
    fill_id TEXT PRIMARY KEY,
    venue TEXT NOT NULL,
    instrument_id TEXT NOT NULL,
    strategy_id TEXT NOT NULL,
    side TEXT NOT NULL,
    size_usd REAL NOT NULL,
    fill_price REAL NOT NULL,
    fee_usd REAL NOT NULL DEFAULT 0.0,
    slippage_bps REAL NOT NULL DEFAULT 0.0,
    ts_ms INTEGER NOT NULL,
    order_id TEXT NOT NULL,
    contribution_id TEXT,
    pnl_usd REAL NOT NULL DEFAULT 0.0,
    is_close INTEGER NOT NULL DEFAULT 0,
    base_qty REAL NOT NULL DEFAULT 0.0,
    quote_qty REAL NOT NULL DEFAULT 0.0,
    state TEXT NOT NULL DEFAULT 'filled'
);
CREATE INDEX idx_fills_ts ON fills(ts_ms DESC);
CREATE INDEX idx_fills_venue_instrument ON fills(venue, instrument_id, ts_ms DESC);
CREATE INDEX idx_fills_order ON fills(order_id);
```

`fills_persist.persist_fill` is idempotent on `fill_id = "{venue}:{order_id}:{open|close}"`. Dashboard `_read_recent_fills` now prefers fills (size_usd / fill_price / pnl_usd / is_close) and falls back to orders (status / order_key only — no qty/side, codex P1 fix).

## Real fill round-trip (Day 6 §2)

`run_okx_round_trip` (BTC-USDT IOC 10 USDT buy + base_ccy sell close) and `run_capital_round_trip` (1-lot EURUSD open + close) both:

- Persist 2 fills to the table on success.
- Return `{"ok": False, "step": <last_step>, "open_fill_id": ...}` when the close leg fails (codex round-2 P1 fix).
- Support `dry_run=True` for CI without venue creds (synthetic Fill pair, deterministic ±pnl).

OKX close uses `tgt_ccy=base_ccy + ord_type=market` and passes `notional_usd=base_qty` so the adapter sends `sz=base_qty` over the wire (codex round-1 P0-2 fix).

## P1.0 ignition (Day 6 §5)

`polaris/scripts/ignite_p1.py` exposes:

```python
async def ignite(
    *,
    duration_sec, tick_sec, db_path,
    paper=False,                   # bootstrap-only when False
    learner_interval_sec=3600,
    real_roundtrip=False,
    full_pipeline=True,
) -> IgnitionReport
```

Bootstrap (paper=False) runs in <1s: init_db idempotent, layer-0 universe count, LearnerScheduler (3 P0 learners) instantiated, vault stamps. Paper mode (`--paper`) starts the smoke loop in full_pipeline mode for `duration_sec` while the LearnerScheduler runs hourly on a background task.

Codex round-1 P0-1 fix: `run_smoke` now accepts `db_path: Path | None` and ignite threads it through, so `ignite(db_path=tmp, paper=True)` trades against the caller's DB rather than `data/polaris.sqlite`.

## Day 1 P2 fix

`update_baseline_from_bars` materializes `bars` once via `list(bars)` so the second per-instrument recompute pass sees the same items. Recompute now anchors at `max(b.ts) per (instrument_id, group_id)` (codex round-1 P1-4 fix) so backfills / out-of-order batches do not anchor against an early ts.
