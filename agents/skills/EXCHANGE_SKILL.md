# 거래소 연동 — 멀티 거래소 구조 지침

## 핵심 개념
시스템은 복수의 거래소를 자산 그룹별로 라우팅하여 사용한다.

거래소별 역할:
- **OKX**: 크립토 전용 (페이퍼 트레이딩만). 가격 피드 + 시뮬레이션 매매
- **Capital.com**: 포렉스/인덱스/커모디티/주식/ETF. 실제 매매 (데모 계정)
- **Alpaca**: 미국 주식/ETF. 실제 매매
- **Binance**: 데이터 전용 (매매 없음). 크로스 거래소 시그널 + OKX 백업 가격

핵심 설계 원칙:
- ExchangeRouter가 자산 그룹 → 거래소 매핑 관리
- 모든 어댑터는 ExchangeAdapter ABC 상속
- 웹소켓 가격 피드 + REST API 데이터 수집 이중 구조
- 각 거래소별 서킷 브레이커 및 재접속 로직 내장

## 분석 방법론
거래소 문제를 진단할 때 다음 순서로 접근:

1. **연결 상태**: 웹소켓 연결이 살아있는지, stale 임계값 이내에 메시지가 오는지 확인
2. **세션 유효성**: Capital.com 세션 만료 여부 (주기적 리프레시 필요), Alpaca 인증 상태
3. **API 레이트 리밋**: 분당 호출 수 추적, 서킷 브레이커 상태 확인
4. **데이터 신선도**: 캐시 TTL 내에 데이터가 갱신되고 있는지, 디폴트 폴백에 의존하고 있지 않은지
5. **주문 실행**: 슬리피지, 수수료 적용이 정확한지, 주문 확인(confirm) 흐름이 완료되는지
6. **라우팅 정확성**: 자산 그룹과 거래소 매핑이 올바른지, 오버라이드 설정 확인

## 고도화 방향
- 주문 실행 품질 개선 — 슬리피지 실측 vs 시뮬레이션 비교
- 새로운 거래소 통합 가능성 탐색 — `/research` 활용
- 웹소켓 재접속 전략 최적화 (현재 고정 백오프 vs 적응형)
- OKX 라이브 트레이딩 전환 준비
- 크로스 거래소 차익거래 시그널 강화
